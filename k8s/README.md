# MealSync — Kubernetes Deployment (local cluster)

Verified on **Docker Desktop Kubernetes v1.34.1** (kubeadm, Docker runtime). Results are in
[../docs/VERIFICATION.md](../docs/VERIFICATION.md). Nothing here provisions cloud resources.

## Layout

```
k8s/
├── 00-namespace.yaml          # namespace "mealsync"
├── 01-configmap.yaml          # DB_HOST=mysql, DB_PORT, DB_NAME, ports, JWT expiry, seeding off
├── 02-secret.example.yaml     # template only — NOT applied by kustomize
├── 03-mysql.yaml              # MySQL 8.4 StatefulSet (utf8mb4) + headless Service + 2Gi PVC
├── 04-backend.yaml            # Spring Boot (2 replicas), wait-for-mysql init container,
│                              #   Actuator startup/liveness/readiness probes on :8081, Service 8080/8081
├── 05-frontend.yaml           # Nginx frontend (2 replicas) + Service
├── 06-ingress.yaml            # Ingress mealsync.local + NodePort 30080 (frontend)
├── 07-hpa.yaml                # backend HPA 1–3 replicas @ 70% CPU (needs metrics-server)
├── 08-monitoring.yaml         # Prometheus (pod discovery, namespace-scoped RBAC) + Grafana
├── grafana/                   # Grafana dashboard + provider (ConfigMaps generated by kustomize)
└── kustomization.yaml
```

## 1. Prerequisites

- Docker Desktop → **Settings → Kubernetes → Enable Kubernetes** (kubeadm) → Apply & restart.
  `kubectl get nodes` must show `docker-desktop   Ready`.
- Images built locally (Docker Desktop's cluster uses the same image store, no push needed):
  ```bash
  docker compose build backend frontend      # produces mealsync-backend:local / mealsync-frontend:local
  ```
  Other local clusters: kind → `kind load docker-image mealsync-backend:local mealsync-frontend:local`;
  minikube → build inside `minikube docker-env`.

## 2. Create the Secret (once)

The Secret is deliberately **not** part of the kustomization, so `kubectl apply -k` can never
replace real credentials with placeholders. Create it from your `.env` with only the five
required keys:

```bash
# run from the repository root (Git Bash / Linux / macOS)
kubectl apply -f k8s/00-namespace.yaml
grep -E '^(DB_USERNAME|DB_PASSWORD|DB_ROOT_PASSWORD|JWT_SECRET|GRAFANA_ADMIN_PASSWORD)=' .env > .env.k8s-secret
kubectl create secret generic mealsync-secret -n mealsync --from-env-file=.env.k8s-secret \
  --dry-run=client -o yaml | kubectl apply -f -
rm .env.k8s-secret                                   # git-ignored (.env.*), removed right away
kubectl get secret mealsync-secret -n mealsync      # shows key count only, never values
```

## 3. Deploy

```bash
kubectl apply -k k8s
kubectl rollout status statefulset/mysql -n mealsync
kubectl rollout status deployment/mealsync-backend -n mealsync
kubectl get pods -n mealsync          # 7 pods, all 1/1 Running
```

The backend pods stay in `Init:0/1` until MySQL accepts connections, then start without
restarts. Seeding is serialized with a MySQL lock, so both replicas can start together safely.

## 4. Access

| What | How | URL |
|---|---|---|
| Frontend (+ `/api` proxy) | NodePort, works out of the box on Docker Desktop | http://localhost:30080 |
| Grafana | `kubectl port-forward -n mealsync svc/grafana 3002:3000` | http://localhost:3002 (admin / `GRAFANA_ADMIN_PASSWORD`) |
| Prometheus | `kubectl port-forward -n mealsync svc/prometheus 29090:9090` | http://localhost:29090/targets |
| Backend API directly | `kubectl port-forward -n mealsync svc/backend 28080:8080` | http://localhost:28080 |

Local ports above are chosen not to collide with the Docker Compose stack.

End-to-end check:
```bash
bash scripts/smoke-test.sh http://localhost:30080
```

## 5. Monitoring in the cluster

- Prometheus discovers **each backend pod** through the Kubernetes API
  (`kubernetes_sd_configs`, role `pod`, namespace `mealsync`) and scrapes the container port
  named `management` (8081). It runs as ServiceAccount `prometheus` with a namespace-scoped
  Role limited to `get/list/watch pods`.
- Grafana is provisioned with the Prometheus datasource (uid `prometheus`) and the dashboard
  **MealSync — Backend (Kubernetes)** (`grafana/mealsync-backend-dashboard.json`), whose panels
  mirror the application section of the Compose dashboard, split per pod.
- Container-level CPU/memory panels exist only in the Compose stack (cAdvisor).

## 6. Known limitations on Docker Desktop

| Item | Status | To enable |
|---|---|---|
| HPA | Created, but shows `cpu: <unknown>` — Docker Desktop has no metrics-server | Install metrics-server (needs `--kubelet-insecure-tls` locally) |
| Ingress `mealsync.local` | Created, no address — no ingress controller installed | Install ingress-nginx and add `127.0.0.1 mealsync.local` to hosts; NodePort 30080 works meanwhile |

## 7. Operations

```bash
kubectl logs -n mealsync -l app.kubernetes.io/name=backend --tail=100
kubectl rollout restart deployment/mealsync-backend -n mealsync     # zero-downtime restart
kubectl delete pod <backend-pod> -n mealsync                        # self-healing: replaced automatically
```

## 8. Stop / teardown

Stop everything but **keep the data** (scale back up or re-apply later):
```bash
kubectl scale deployment --all -n mealsync --replicas=0
kubectl scale statefulset mysql -n mealsync --replicas=0
```

> ⚠️ `kubectl delete -k k8s` also deletes the `mealsync` **Namespace** (it is part of the
> kustomization), and deleting the namespace or the PVC `mysql-data-mysql-0`
> **permanently deletes the database data**.
