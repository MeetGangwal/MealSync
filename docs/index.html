From menu to plate in four steps

The mess has one billing counter, one thali counter and one counter for everything else. MealSync removes the billing queue and spreads pickups across the meal.

  1. 01

    Browse today’s menu

    Real dishes, prices and remaining portions straight from the kitchen.

  2. 02

    Pick a pickup slot

    Each 15-minute window has a fixed number of places, enforced by the server.

  3. 03

    Confirm the order

    Pay when you order (test simulator) or choose cash at pickup.

  4. 04

    Collect and go

    Show the QR ticket at the right counter during your slot.

Built to be trusted with real orders

The browser never decides a price, a stock level or a role. The server does, every time.

Server-side prices & stock

Totals are recalculated and stock reduced under row locks. A rejected order rolls back completely.

Slots that can’t overfill

A locking read counts bookings, so two simultaneous orders can’t take the last place.

Honest numbers

Payment records, analytics and monitoring are computed by the backend — no mock charts.

The stack

A Spring Boot API and a React app, packaged for Docker Compose and Kubernetes, with Prometheus and Grafana watching.

Run it in three commands

Needs Docker Desktop. The script builds everything, waits until it is healthy and prints the URLs.

git clone https://github.com/MeetGangwal/MealSync.git && cd MealSync
cp .env.example .env        # fill in the CHANGE_ME values
bash scripts/run-local.sh   # → http://localhost:3000
